## Piece 3 — an e-mail when the site is down

Done. A watchdog on the host (`deploy/site/watchdog/seasonal-watchdog.sh`, plain bash and
curl) runs every 2 minutes from a systemd timer that every installer run installs and enables.
It is outside the site's container and not tied to Docker. It checks `https://<site>/api/health`
and, with calls, `https://<calls domain>/`, through this server's own web server (`curl
--resolve` to 127.0.0.1). After 2 failed checks in a row: one "Down" e-mail; when both answer:
one "Back up" e-mail; nothing in between; a failed send is tried again on the next run.
Details: docs/DEPLOYMENT.md, "An e-mail when the site is down" (with the Google app password
steps and the whole-server limit).

- **Where things live**: the recipient is Admin → Settings → **Alerts → "Outage alert
  address"**, which the site writes into `outage-alert-address` in its data volume (the host
  reads it there, also while the site is down). The mail account is the installer's optional
  questions (SMTP server, port, user, password) into `/etc/seasonal/outage-smtp` (root, 600,
  never printed, kept on `--update`; `--outage-mail` asks again; an answers file gives
  `OUTAGE_SMTP_PASSWORD_FILE`).
- **Smaller option taken: the site never holds the mail password.** A root-only file is not
  readable by the site's container, so the site cannot send itself. "Send a test e-mail"
  therefore asks the watchdog (a request file beside the address), which sends it on its next
  run (at most 2 minutes) and writes back "sent" or "failed <reason>"; the admin page shows
  that, with "Check again".
- **Reused**: the settings registry (a new "Alerts" group, text kind with its own check),
  `changeSetting`'s audit, the installer's `ask` / `ask_optional` / `ask_secret`, `kv_set` and
  its state file, the backup timer's way of writing units with the checkout's path, the volume
  lookup (`recordings_host_dir` now builds on the new `site_data_host_dir`).
- **Not changed**: the privacy page. Nothing about members is stored: the address is the
  admins' own setting, the test request and its answer are two times in small files.
