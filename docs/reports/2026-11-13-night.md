## Piece 1 — ended call, empty chat column

### Reproduced

In a browser against the run's own server (built client), a call created, started and ended
by the admin, the page opened as the admin, a member and a guest:

- **Ended, no messages**: the column was the title and an empty white box (the list's frame
  fills the column); the only text, "You can read this room, but not write in it.", sat under
  the box (at a short window below the fold). That is what was seen.
- **Ended, with messages**: the messages showed, read-only, with the same general line.
- **The room removed**: no blank column is possible. The chat room is deleted only with the
  call (`server/src/calls/deleteCall.js`), and the page then says "No such call."; a call whose
  room row is gone gets `chatRoom: null` (`server/src/calls/routes.js:81`, the column is not
  drawn). The cleanup that removes rooms is the call service's (`server/src/calls/service.js`,
  the LiveKit room), not the chat room. Nothing to fix there.

### Done

- After the call, the column says **"This call's chat is closed."** instead of the general
  line, and an empty one says **"No messages in this call."** inside its box. With messages
  they show read-only, as before.
- `ChatPanel` gains two optional inputs, `emptyText` and `readOnlyNote` (docs/CHAT.md);
  `CallChat.jsx` passes them while the call's status is `ended`. Reused: the chat's own
  `.chat-note` line style (the empty line is that style, placed over the top of the list,
  like the existing "New messages" button in the same frame).
- `useChatRoom` reports `loaded` (the room's messages have arrived for this reader), so the
  empty line never shows while the messages are still on their way.
- Test `client/src/calls/callChatEnded.test.jsx` (3): empty, with messages, still loading.
  It fails before the fix. Breaks: the ended props off → all 3 red; the loaded check off → the
  "still loading" test red (and the first, which then needed to wait for the room list: made
  it wait, the break still caught by the third). Restored, 204 tests in calls and chat green.
- Browser check after the fix (admin, member, guest; empty and with messages): the texts
  above, at the top of the box and under it.
