## Piece 3 — the encrypted backup scripts' test under load

### Measured

The test is "the scripts: encrypted by default, a key required; restore from the decrypted
.tar" in `server/test/backupEncrypted.test.js`. A timed copy (not committed) wrote each step's
time to a file; it ran alone, and three times started 20 s after the full server suite, beside
it. The full suite itself, in all three loaded runs, **timed out on exactly this test**
(48.9 s, 55.6 s, 53.2 s against the 45 s default): reproduced 3 of 3.

| Step (ms)                            | Alone | Load 1 | Load 2 | Load 3 |
| ------------------------------------ | ----: | -----: | -----: | -----: |
| the site (two accounts, a sticker)   |   214 |    382 |    339 |    530 |
| `backup.mjs` without a key (refused) |  1010 |   3082 |   3576 |   2497 |
| `backup.mjs` with the key            |  1477 |   6233 |   4382 |   3978 |
| decrypt (in the test)                |    46 |     89 |     37 |     38 |
| `restore.mjs --check`                |  4567 |  12710 |  10710 |  14302 |
| `restore.mjs` into a new place       |  2644 |   9583 |  18732 |  11700 |

**Cause**: four fresh node processes of the real scripts. Each loads part of the server before
doing anything; for `restore.mjs` that is 1.1–1.3 s of imports on a quiet machine, almost all of
it `server/src/accounts/deletionJournal.js` (it pulls in the account deletion and with it much
of the server). The work itself is tiny (two accounts, one file; decrypting takes 40–90 ms).
Under load every process start costs 3–4 times as much. That is not a slowness of the backup or
the restore: the same steps in-process (the first test) take under a second.

### Done

- The test keeps all four runs and gets a timeout of its own, **120 s** (`SCRIPTS`, about twice
  the worst measured 56 s), with the measurement in a comment. The fixture was already the
  smallest that tests something; no step skipped. The project's way of a per-test timeout
  (`botImages.test.js`) reused.
- Confirmed under the same load: the full server suite 831/831, the file beside it 4/4.
- Break: the timeout set to 5 s → the test red ("Test timed out in 5000ms"); restored.

## Piece 5 — security review since 2026-11-10

Report only; nothing fixed. Scope: master 0d61ce5 against the changes since the audit of
2026-11-10 (polls with chat polls and anonymous vote changes, recording share pages, web push,
member profiles, the session-ended handling, the account page, the race slug). Read in the code,
with small node checks of the shared modules; no server run against data. Counts: **High 0,
Medium 2, Low 8, Info 6**. "Checked in code" marks the ones confirmed a second time for this
sheet; the others are the review's, read once.

### Medium

- **M1 — web push: no cap on subscriptions per account, and every call start sends to all at
  once.** `server/src/push/routes.js:77` (POST `/subscriptions`, only `pushSubscribe` 30 a
  minute per account), `server/src/push/store.js:17` (insert, no count),
  `server/src/push/send.js:50-56` (`Promise.allSettled` over every row, no concurrency limit; a
  row goes only on 404/410, a failed fetch keeps it and logs a line). How: a member posts made-up
  endpoints on the allowed push hosts, up to about 43,000 a day. A user would see: a slow site
  around each call start, log flooding, possibly the push services throttling the site's key.
  Latent, not observed. Checked in code.
- **M2 — the privacy page says nothing about polls.** `server/src/info/seed/privacy.md` (no
  "poll"); `server/src/polls/store.js:294` and `routes.js:100`: in a poll that is not anonymous
  the voters' usernames per answer show to everyone once it ended, guests included (`GET
/api/polls` is public); free-text answers go to staff; the temporary ballot links of anonymous
  polls are in the backups taken meanwhile; anonymous ballots stay after an account's deletion.
  A user would see: their name next to their vote for logged-out visitors, with nothing on the
  privacy page (which promises profiles "never to guests"). A statement gap, not a code bug;
  whether guests should see names is the owner's call.

### Low

- **L1 — share page: a `$` in a call title breaks the head markup.**
  `server/src/calls/recordingShare.js:85`: `.replace('</head>', string)` expands `$'`, `` $` ``
  and `$&`. A title with `$'` pastes the rest of `index.html` into `og:title`. Seen: a broken
  preview card on `/recordings/<id>`; not XSS (escaped, CSP). Only staff set titles. Checked in
  code (node: the replacement expands). Fix: a replacer function.
- **L2 — service worker: `/\host` passes the click check.** `client/public/sw.js:31`:
  `/^\/(?!\/)/` accepts `/\evil.example`, which resolves to `https://evil.example/` (checked
  with node). Today the URL comes only from the server's own payload, so defence in depth;
  `shared/localPath.js` has the right rule. Latent, not observed. Checked in code.
- **L3 — votes: wrong types give 500s or junk rows.** `shared/pollRules.js:74-76`,
  `server/src/polls/store.js:179,184`: for a text poll `options` is never checked (`{}` → 500;
  another poll's option ids stored as this ballot's), a non-string `text` passes and then throws.
  Seen: "Something went wrong", or junk only the voter sees. Latent, not observed.
- **L4 — every vote reloads the whole poll summary on every member's open page.**
  `server/src/polls/routes.js:89,176`, `client/src/polls/usePolls.js:52`,
  `server/src/polls/store.js:314-334` (all polls ever, several queries each). Seen: a slower
  site in busy votes, worse as the archive grows. Latent, not observed.
- **L5 — nginx's deny of the game feeds is case-sensitive, Express is not.**
  `deploy/install/lib/games.sh:120`: `/api/games/race/Account-Changes` passes nginx and reaches
  the feed; it still needs the sync token (timing-safe). Caddy is not affected. Seen: nothing.
  Latent, not observed.
- **L6 — account page: `/account#%` gives a blank page.** `client/src/pages/AccountPage.jsx:50`:
  `decodeURIComponent` throws during render, and the app has no error boundary. Seen: a blank
  page until the anchor is removed. Latent, not observed in a browser; the throw checked with
  node.
- **L7 — web push stays on after logout; an unfinished turn-on can finish under the next
  account.** `client/src/session/SessionContext.jsx:68-71`, `client/src/notify/pushPending.js`.
  Seen: "… has started" notices on a shared device after logging out, or the switch "on" for
  someone who never turned it on (within 90 s in the same tab). Latent, not observed.
- **L8 — a room poll's card ignores chat mutes, bans and the message limit.**
  `server/src/chat/mount.js:251-258`, `server/src/chat/viewer.js:84-85`: `canWrite` without the
  sanction check. Seen: poll cards from a muted organiser. Latent, not observed; organisers are
  trusted.
