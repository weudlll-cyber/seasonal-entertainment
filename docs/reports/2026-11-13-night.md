### Step 2 — M1: web push, 10 devices per account, a few sends at a time

- **The cap**: `saveSubscription` (`server/src/push/store.js`) keeps at most `MAX_PER_ACCOUNT`
  (10) rows per account in the same transaction; beyond that the one used least recently goes,
  never the one just saved. "Used" is a new column, `used_at`: set when the device turns it on,
  when its account page asks whether it is on (`POST /status`, now `checkSubscription`, which
  marks it while it answers), and when a message is delivered (`markDelivered`). An older table
  gets the column with each row's turn-on time (`migratePush`, `server/src/push/schema.js`,
  through the existing `addMissingColumns`). The same device again is no new one; another
  account's devices are not counted.
- **Sending**: `deliverAll` (`server/src/push/send.js`) runs `sendInFlight` workers (8,
  `server/src/push/config.js`), each taking the next device, so at most 8 requests are open at
  once. A small worker pool, not fixed batches: the same bound, and a slow device never holds
  up the rest of its batch. The start was already not waiting (`wentLive`, `app.js`); now
  even reading the subscriptions runs after the start's request (`setImmediate`), and an error
  there is logged instead of being an unhandled rejection.
- **Privacy**: the push entry says at most 10 devices and that the last-use time is stored;
  the step-1 text is recorded as an earlier version.
- **Tests** (`push.test.js`, each red before the fix): an 11th replaces the least recently used
  (a status check counting as use; another account untouched; the same device again replaces
  nothing); a delivered message counts as use; 12 devices with `sendInFlight` 3 against a push
  service that holds each request 40 ms: at most 3 open, all 12 reached; an older table gets
  `used_at`. `infoSeed.test.js`: a privacy page from before the cap gets the new text.
- **Breaks**, each red, restored: the cap one higher (2 red); the least recently used order
  reversed (2 red); the status check not marking use (1 red); deliveries not marking use (1
  red); every device at once (1 red); the migration not filling `used_at` (1 red); the hash
  left out (1 red).
