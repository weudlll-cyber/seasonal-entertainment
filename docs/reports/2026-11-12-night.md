## Piece 1 — installable site and a "call started" web push

### Done

- **Installable**: `client/public/manifest.webmanifest` (name, short name "Seasonal", start
  `/`, standalone, theme colour `#0c1538`, background `#fbfaf6` from the tokens), linked from
  `client/index.html` with the Apple touch icon and `<meta name="theme-color">`. Icons in
  `client/public/icons/`, made from the brand emblem by the new `scripts/build-app-icons.mjs`
  (192, 512, maskable 512, Apple 180).
- **Service worker** `client/public/sw.js`: only `push` and `notificationclick`; no fetch
  handler, no cache. Registered after the page's load for every visitor
  (`client/src/app/serviceWorker.js`, from `main.jsx`).
- **The push**: one only, when a call goes live through the start route (the only place a call
  goes live, `server/src/calls/routes.js`), "<call title> has started", a click opens
  `/calls/<id>` (or focuses a tab already there). Members only, opt-in per device.
- **The switch**: "When a call starts (on this device, also while the site is closed)" in the
  account page's Notifications section (`client/src/notify/PushSwitch.jsx`, inside the existing
  `NotificationSettings.jsx`; the browser steps in `client/src/notify/push.js`). Hidden without
  keys or browser support. Its state comes from the server: a browser's subscription may still
  be another account's that used it.
- **Server** (`server/src/push/`: schema, store, config, routes, send):
  - Library: **`web-push` 3.6.7, MPL-2.0**, pinned exactly; `npm audit` is clean.
  - Routes under `/api/push`, members only; a per-account limit like the other member routes
    (`pushSubscribe`, 30 a minute).
  - Subscriptions per account and device (`push_subscriptions`). Dropped when the push service
    answers 404 or 410; removed when an account is locked (`setLocked`); gone with a deleted
    account (cascade). Locked accounts are also skipped when sending.
  - Sending never delays or fails the start: the route hands the call to `wentLive` without
    waiting. A test with a push service that never answers proves the start still answers.
- **Installer**: `deploy/install/lib/push.sh` makes the VAPID pair once with openssl into
  `site.env` (never printed; kept on re-runs and `--update`; a half pair is made again whole).
  `deploy/test/push.test.sh` (CI, shellcheck) checks this, including that the two keys are a
  real pair.
- **Docs**: docs/CALLS.md "Push when a call starts"; docs/DEPLOYMENT.md "Web push" (keys,

### Forks taken (the smaller option)

- **`web-push` 3.6.7, not 4.0.0**: 4.0.0 is a major release, 5 days old; 3.6.7 has been stable
  since January 2024 and audits clean.
- **Restore**: restore.mjs restores the database only; no secret of `site.env` is in a backup
  or restored by it (`SECRET_ENCRYPTION_KEY` is copied by hand on a new server). The VAPID keys
  are treated the same: kept in `site.env`, copied by hand on a new server
  (docs/DEPLOYMENT.md). Each subscription remembers the key it was made for; one made for other
  keys is dropped at the next sending, so a restore with new keys never sends failing pushes.
  Members then turn the switch on again.
- **Endpoints**: only the browsers' push services (Google, Mozilla, Apple, Microsoft) are
  accepted as push addresses, over https. Otherwise a member could make the server post to any
  address. A browser using another push service would not get the switch working; none is
  known.
- **VAPID subject**: the site's own https address (`PUBLIC_ORIGIN`); no new setting. Without
  https (development) a fixed `mailto:` stands in.
- **Icons**: your original logo file is not on this PC, so the icons are made from the
  committed 420 px emblem; the 512 px ones are slightly scaled up. A sharper set needs the
  original: run `scripts/build-brand-images.mjs` with it, then `scripts/build-app-icons.mjs`.
- **e2e keys**: the browser tests' push keys are derived at start from a fixed phrase, not
  written into the file: a literal private key would look like a leak to gitleaks.
