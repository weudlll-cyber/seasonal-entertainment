## Security fixes after the independent review (SE-SECURITY-FIX-1, 2026-10-17)

| Finding                                | Fix                                                                                                                                                                                                                                                                                      |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 10 — "wrong origin" on 5380            | The Vite proxy rewrote `Host` to `127.0.0.1:3800` for `/api` while the browser sent `Origin: http://localhost:5380`, so every state change in development was refused (chat, login, register, logout, admin saves). The proxy now passes `Host` on unchanged; CSRF is exactly as strict. |
| 8 — WebSocket origin                   | The upgrade compared the host only; it now compares the full origin, scheme included, with the CSRF guard's own `selfOrigin()` rule.                                                                                                                                                     |
| 1 — chat skipped staff 2FA             | One viewer rule for HTTP and WebSocket: an organiser or admin without the required 2FA counts as a member (no Organisers room, no Announcements, no hidden messages, no moderation). Commit `603b78c`.                                                                                   |
| 2 — sockets kept old rights            | Every subscribe and push re-checks the account as it is now; logout, lock, role and password changes close the affected sockets. Commit `603b78c`.                                                                                                                                       |
| 9 — guests only in General by seed     | Guests write only in rooms with the new guest-writable flag (enforced in code; shown and editable in Admin → Chat; off for new rooms). Existing databases are migrated on start: General keeps guest writing.                                                                            |
| 3 — guest limits tied to the cookie    | Per-IP limits for guests, in memory only: 20 messages per minute, 20 new guest names per hour. Guest names now have six base32 characters (about a billion); no free name answers 503, never 500.                                                                                        |
| 4 — 2FA enrolment and sessions         | Starting the 2FA setup needs the current password (disabling already did; restarting a setup goes through the same step). Turning 2FA on or off ends every other session of the account through the existing session epoch and closes its other chat sockets.                            |
| 7 — pending 2FA login survived a reset | The half-way login remembers the session epoch; a password reset in between makes the second step answer `login_expired`.                                                                                                                                                                |

  - The Mining page names the mining programs but sends readers to the official mining page for

  - Sunday 21:00: the PDFs say "S.T badge race time - Rewards payed out in POL"; the event is

  - No event has a link yet (the sources give none).
- **Chat retention period:** 90 days by default (`CHAT_RETENTION_DAYS`). Please confirm or name
  another period.
- **Audit log retention:** kept without automatic deletion (Privacy says so). Name a period if you
  want one.
- **Age confirmation is not stored.** The "at least 14" checkbox is required, but no "confirmed
  at" timestamp is kept (and no date of birth, as decided). A timestamp is a small change.
- **Email addresses are not verified.** No mail is sent; a confirmation mail and password reset by
  mail need a mail provider you choose.

  back with a new guest name. Durable bans for guests remain impossible without storing something
  about them (for example the IP address), which the site deliberately does not do (unchanged
  decision). Since SE-SECURITY-FIX-1, per-IP limits held only in memory slow such a guest down:
  20 guest messages per minute and 20 new guest names per hour from one address.
- **CSRF strict by default** (`CSRF_STRICT=true`): any state-changing API call without an Origin
  header is refused, also in development. Stricter than the race game.

   **Admin → Audit log** shows each change with before and after.
5. In a private window, **Register** a second account. As devadmin, **Admin → Users**: make it an
   organiser. In the private window it now sees the 2FA banner; in **Chat** your devadmin window
   shows Hide / Mute / Ban on its messages.

## Config keys added tonight

| Key                   | Default                        | What it does                                                                             |
| --------------------- | ------------------------------ | ---------------------------------------------------------------------------------------- |
| `NODE_ENV`            | unset                          | `production`: Secure cookies, `SESSION_SECRET` required, 2FA rule cannot be switched off |
| `DATABASE_PATH`       | `data/seasonal.db`             | the SQLite file                                                                          |

| `PUBLIC_ORIGIN`       | from the Host header           | the site's own origin for CSRF and WebSocket checks (set behind a proxy)                 |
| `TRUST_PROXY`         | `0`                            | number of reverse proxies in front                                                       |
| `COOKIE_SECURE`       | `true` in production           | Secure session cookie                                                                    |
| `CSRF_STRICT`         | `true`                         | refuse state changes without Origin/Referer                                              |
| `BCRYPT_COST`         | `12`                           | password hashing cost (4–15)                                                             |
| `REQUIRE_STAFF_2FA`   | `true`                         | organisers/admins must use 2FA; `false` only outside production                          |
| `CHAT_RETENTION_DAYS` | `90`                           | chat messages older than this are deleted                                                |

`server/src/config.js` (not environment keys).
