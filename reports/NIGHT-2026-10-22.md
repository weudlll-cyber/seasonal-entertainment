## Piece 1 — Security settings

### Chat connection limits

- **Limits**: at most 5 open chat connections per member account, counting every tab, the chat
  drawer and chats embedded on other sites together. Guests without an account get at most 20
  per address. Both are config keys with these defaults (`CHAT_MAX_CONNECTIONS_PER_MEMBER`,
  `CHAT_MAX_GUEST_CONNECTIONS_PER_IP`, in `.env.example`).
- **Refusal**: one more connection is accepted and closed at once with close code 4008
  (`TOO_MANY_CONNECTIONS`). A refused HTTP upgrade would look like a network error to the
  browser.
- **Message**: the chat area (room panel and direct-message panel) shows "You have the chat
  open in too many windows (at most 5). Close one and try again." with "Try again".
- **No retry loop**: the page tries again only when the reader presses "Try again", or when
  another tab of the same browser closes its connection (a `BroadcastChannel` message). An
  ordinary drop still reconnects after 3 seconds.
- **Address**: the one our own proxies forwarded, as Express's `req.ip` reads it with
  `TRUST_PROXY` hops (`clientIp`).
- **Counted by**: the hub (`countOpen`), which already knew every socket's session.
- **Reused**: `sessionUser` (who a session belongs to), `ChatNotice`'s classes, the
  `chat-link-button` style, the test helpers `listeningChat` / `connect` / `cookieOf`, and
  `FakeSocket`, which gained `closeByServer(code)`.

### Sessions: 7 days without use

- **Expiry**: a signed-in session ends after 7 days without use.
- **Renewal**: every authenticated request renews it to 7 days from then, at most once a minute
  (`renewSession`: the `usedAt` stamp, the cookie's and the stored expiry). The store's own
  per-request "touch" write is switched off.
- **Refusal**: a session whose `usedAt` is over 7 days old is refused (`sessionUser`, so the
  chat socket too).
- **Existing sessions**: signed-in sessions from the 30-day rule are capped at 7 days from the
  server's start.
- **Guests**: a guest's session (only a guest name) keeps its 30 days; the guest-name release
  rule depends on it.
- **Privacy draft**: the session line now says "after 7 days without use".

## Piece 2 — Calls linked to bot events

- **Picker**: an organiser picks one of the event bot's upcoming occurrences, or "No event",
  when creating a call (the new-call form). The same picker sits on a planned call's card on
  the Calls page, so the link can be changed later; there was no call editing before, and
  this is its only field.
  - **Source**: the next 30 days, scheduled only (`GET /api/calls/bot-occurrences`, organisers
    and admins), read through the existing bot reader (`readBotDb`, `botOccurrences`).
  - **Saved by**: `POST /api/calls { botOccurrenceId }` and `PUT /api/calls/:id/event`
    (planned calls only, audited as `call.event`). An occurrence that is not an upcoming one
    is refused.
- **Stored on the site only**: the call's `bot_occurrence_id` and `bot_occurrence_start` (two
  new columns, added to older databases by `migrateCalls`). The bot's file is only read.
- **Shown**:
  - "Up next" and `/events`: the linked occurrence shows "Listen on this site" (to the call's
    page), and the call is not listed a second time. While the call is live, the event says
    "Live now".
  - The call's page: "Event: <name>".
  - Matching is by the occurrence's id **and** start, from the Calls page's own answer
    (`withCalls`, which replaces `callEntries` / `byStart` in `client/src/calls/callEntries.js`).
    A guest sees the link only for the live and planned calls the Calls page shows them.
- **Vanished or moved**: the call keeps its own time and is listed as itself; its page names no
  event; no error. An unreadable bot file counts the same (logged).
- **Unlinked calls** behave as before.
- **Reused**: `readBotDb`, `botOccurrences`, `callSteps`, `validBody`, `recordAudit`, the
  rate limit `callManage`, `formatWhen`, `useCalls` (piece SE-UPNEXT-CALLS-1), and the form
  field styles. The shared field rule now also covers a select outside a form card, and a
  long option no longer widens its form.
