## How to try a call (eye test)

The dev server on port 5380 runs with the local call server (`npm run dev:calls`, LiveKit
1.13.10 on 7880). Window 1: log in as `devadmin` → **Calls** → **New call** → **Start …** →
**Open …** → **Join call** (you are on the stage; allow camera and microphone). Window 2 (a
private window, or another browser): log in as a second account (or stay a guest) → **Calls** →
**Open …** → **Join call** → **Raise hand**. In window 1 the hand shows first under Listeners →
**Invite**; window 2 now has Microphone, Camera and Share screen. **End call for everyone**
ends it for both.

# SE-CALLS-2 — fixes from the eye test of 2026-10-18 (Edge, two windows)

Same branch, same draft PR #6. **Nothing is merged.**

## DONE (SE-CALLS-2)

- **The listener now sees a shared screen**, and the presenter no longer gets "Something went
  wrong on the server.". Cause (measured): the development database's calls table was older
  than the spotlight, so every spotlight request failed (`no such column: spotlight_identity`),
  and the listener's page showed a share only through that spotlight. Now the table is brought
  up on start, every page shows a share by itself, and a failed spotlight update is only logged.
- **No sound with the share**: in Chrome and Edge the page explains which choice carries sound
  ("Entire screen" with "Share system audio", or a tab with "Share tab audio") and offers
  **Share again with sound**; only Firefox and Safari get the browser hint.
- **Listeners as chips**: initial circle and name, raised hands first in autumn orange,
  a compact **Invite** inside the chip, the site's search field; hidden listeners as "A
  listener" with a neutral circle and numbered Invite buttons.
- **Call chat like the drawer**: one row — a single-line field and icon buttons. The drawer's
  chat had the same tall composer before; both now share the compact one.
